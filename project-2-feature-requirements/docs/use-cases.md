# Сценарии использования: «Семейный аккаунт»

## UC-1. Создание семейного аккаунта и приглашение участника

| Поле | Значение |
|---|---|
| **Актор** | Владелец (глава семьи) |
| **Предусловие** | У пользователя есть обычный аккаунт, подтверждён телефон |
| **Триггер** | Пользователь выбирает «Создать семейный аккаунт» |
| **Результат** | Создан семейный аккаунт, приглашён хотя бы один участник |

**Основной сценарий:**
1. Пользователь открывает раздел «Семья» и нажимает «Создать семейный аккаунт».
2. Система создаёт аккаунт и назначает пользователя владельцем.
3. Владелец нажимает «Пригласить участника», вводит номер телефона и выбирает роль.
4. Система отправляет приглашение.
5. Приглашённый открывает приглашение, принимает согласие на обработку ПДн и подтверждает вступление.
6. Система добавляет участника в аккаунт; владелец видит его в списке.

**Альтернативные сценарии:**
- 3a. В аккаунте уже 6 участников → система блокирует приглашение, показывает лимит.
- 5a. Приглашённый отклоняет согласие → участник не добавляется, владелец видит статус «Приглашение отклонено».
- 5b. Приглашённый — уже владелец другого семейного аккаунта → система предупреждает, что нужно выйти из своего, прежде чем вступить.

## UC-2. Заказ подростком с проверкой лимита

| Поле | Значение |
|---|---|
| **Актор** | Участник-подросток (основной), Владелец (вторичный) |
| **Предусловие** | Подросток в аккаунте, задан лимит трат, есть общий способ оплаты |
| **Триггер** | Подросток оформляет заказ |
| **Результат** | Заказ оформлен сразу либо после подтверждения владельца, либо отклонён |

**Основной сценарий:**
1. Подросток собирает корзину и нажимает «Оформить».
2. Система проверяет: сумма заказа ≤ доступного остатка лимита.
3. Остатка достаточно → система оформляет заказ, списывает с общего кошелька, уменьшает остаток лимита.
4. Подросток видит «Заказ оформлен».

**Альтернативный сценарий (превышение лимита):**
- 3a. Остатка недостаточно → система ставит заказ в статус «Ожидает подтверждения» и отправляет владельцу push.
- 3b. Владелец подтверждает → заказ оформляется, деньги списываются.
- 3c. Владелец отклоняет → заказ отменяется, списания нет, подросток уведомлён.
- 3d. Владелец не отвечает в течение 2 часов → заказ автоматически отменяется, подросток уведомлён.

Диаграмма последовательности этого сценария — в [README кейса](../README.md#ключевой-сценарий-use-case-2-заказ-подростком-с-лимитом).

## UC-3. Контроль трат владельцем

| Поле | Значение |
|---|---|
| **Актор** | Владелец |
| **Предусловие** | В аккаунте ≥ 2 участников, есть история заказов |
| **Триггер** | Владелец открывает историю/отчёт |
| **Результат** | Владелец видит разбивку заказов по участникам и суммам |

**Основной сценарий:**
1. Владелец открывает «Семья → История».
2. Система показывает список заказов с указанием участника-автора, суммы и даты.
3. Владелец может отфильтровать по участнику и периоду.
4. По участнику-подростку владелец видит остаток лимита и может его изменить.
