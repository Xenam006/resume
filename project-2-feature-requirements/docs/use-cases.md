# Сценарии использования: «Семейный аккаунт»

## UC-1. Создание семейного аккаунта и приглашение участника

| Поле | Значение |
|---|---|
| Актор | Владелец (глава семьи) |
| Предусловие | Есть обычный аккаунт, телефон подтверждён |
| Триггер | Пользователь выбирает «Создать семейный аккаунт» |
| Результат | Аккаунт создан, приглашён хотя бы один участник |

Основной сценарий:
1. Пользователь открывает раздел «Семья» и нажимает «Создать семейный аккаунт».
2. Система создаёт аккаунт и делает пользователя владельцем.
3. Владелец нажимает «Пригласить участника», вводит телефон и выбирает роль.
4. Система отправляет приглашение.
5. Приглашённый открывает его, принимает согласие на обработку ПДн и подтверждает вступление.
6. Система добавляет участника, владелец видит его в списке.

Альтернативы:
- 3a. В аккаунте уже 6 участников — система блокирует приглашение и показывает лимит.
- 5a. Приглашённый не принимает согласие — участник не добавляется, владелец видит «Приглашение отклонено».
- 5b. Приглашённый уже владелец другого семейного аккаунта — система просит сначала выйти из своего.

## UC-2. Заказ подростком с проверкой лимита

| Поле | Значение |
|---|---|
| Актор | Участник-подросток (основной), Владелец (вторичный) |
| Предусловие | Подросток в аккаунте, задан лимит, есть общий способ оплаты |
| Триггер | Подросток оформляет заказ |
| Результат | Заказ проходит сразу, после подтверждения владельца или отклоняется |

Основной сценарий:
1. Подросток собирает корзину и нажимает «Оформить».
2. Система проверяет: сумма заказа не больше остатка лимита.
3. Остатка хватает — система оформляет заказ, списывает с общего кошелька, уменьшает остаток.
4. Подросток видит «Заказ оформлен».

Если лимит превышен:
- 3a. Остатка не хватает — заказ уходит в статус «Ожидает подтверждения», владельцу приходит push.
- 3b. Владелец подтверждает — заказ оформляется, деньги списываются.
- 3c. Владелец отклоняет — заказ отменяется, списания нет, подросток уведомлён.
- 3d. Владелец молчит 2 часа — заказ отменяется автоматически, подросток уведомлён.

Диаграмма последовательности этого сценария — в [README кейса](../README.md#ключевой-сценарий-use-case-2-заказ-подростком-с-лимитом).

## UC-3. Контроль трат владельцем

| Поле | Значение |
|---|---|
| Актор | Владелец |
| Предусловие | В аккаунте ≥ 2 участников, есть история заказов |
| Триггер | Владелец открывает историю/отчёт |
| Результат | Владелец видит заказы по участникам и суммам |

Основной сценарий:
1. Владелец открывает «Семья → История».
2. Система показывает список заказов с автором, суммой и датой.
3. Владелец фильтрует по участнику и периоду.
4. По подростку владелец видит остаток лимита и может его изменить.
