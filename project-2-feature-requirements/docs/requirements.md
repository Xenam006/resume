# Требования: фича «Семейный аккаунт»

## 1. Бизнес-требования (BRD)

| ID | Бизнес-требование | Обоснование |
|---|---|---|
| BR-1 | Семья должна иметь возможность объединить до 6 человек в один аккаунт с общими адресами и оплатой | Семьи фактически уже делят один аккаунт; легализуем сценарий |
| BR-2 | Владелец аккаунта должен контролировать траты участников (лимиты, подтверждение) | Главная боль родителей — контроль бюджета |
| BR-3 | Подросток должен иметь возможность заказывать самостоятельно в заданных рамках | Расширяет аудиторию активных заказчиков |
| BR-4 | Обработка персональных данных членов семьи должна соответствовать 152-ФЗ | Требование юристов, иначе фичу нельзя запускать |
| BR-5 | Фича должна увеличить частоту заказов и retention без роста нагрузки на поддержку | Экономическое обоснование инвестиций |

**Цель (SMART):** в течение 3 месяцев после запуска ≥ 20% активных аккатунов подключают ≥ 1 участника, а частота заказов у семейных аккаунтов на ≥ 15% выше, чем у контрольной группы.

## 2. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-1 | Пользователь может создать семейный аккаунт и стать его владельцем | Must |
| FR-2 | Владелец может пригласить участника по номеру телефона / ссылке и указать его роль (взрослый/подросток) | Must |
| FR-3 | Владелец может удалить участника; удалённый теряет доступ к общим данным | Must |
| FR-4 | Участники используют общие сохранённые адреса доставки | Must |
| FR-5 | Участники оформляют заказ на общий способ оплаты / кошелёк | Must |
| FR-6 | Система хранит, каким участником оформлен каждый заказ | Must |
| FR-7 | Владелец может задать участнику-подростку лимит трат (в ₽ за период) | Should |
| FR-8 | При превышении лимита заказ уходит на подтверждение владельцу (push) | Should |
| FR-9 | Общий список покупок, видимый всем участникам | Could |
| FR-10 | Уведомление участникам «кто-то оформил общий заказ» | Could |

---

## 3. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-1 | Безопасность | Участник видит только разрешённые ему данные; платёжные реквизиты не раскрываются участникам в явном виде (токенизация) |
| NFR-2 | Приватность / 152-ФЗ | При приглашении участник даёт согласие на обработку ПДн; для подростка до 14 лет действия выполняет законный представитель |
| NFR-3 | Производительность | Проверка лимита и оформление заказа — не дольше 1 с в 95% случаев |
| NFR-4 | Надёжность | Двойное списание с общего кошелька исключено (идемпотентность операций оплаты) |
| NFR-5 | Доступность | Онбординг в семейный аккаунт — не более 3 экранов |

## 4. User stories с критериями приёмки

### US-1. Создание семейного аккаунта
> Как пользователь, я хочу создать семейный аккаунт, чтобы объединить заказы и оплату с близкими.

**Критерии приёмки (Given / When / Then):**
- **Given** у пользователя обычный аккаунт, **When** он нажимает «Создать семейный аккаунт», **Then** он становится владельцем нового семейного аккаунта и видит экран управления участниками.
- **Given** пользователь уже является владельцем семейного аккаунта, **When** он открывает создание ещё одного, **Then** система сообщает, что можно быть владельцем только одного семейного аккаунта.

### US-2. Приглашение участника
> Как владелец, я хочу пригласить члена семьи и задать ему роль, чтобы он мог заказывать на общих условиях.

**Критерии приёмки:**
- **Given** владелец на экране управления, **When** он вводит телефон и выбирает роль «взрослый», **Then** приглашённому приходит приглашение, а после согласия он появляется в списке участников с ролью «взрослый».
- **Given** в аккаунте уже 6 участников, **When** владелец приглашает ещё одного, **Then** система блокирует приглашение и показывает лимит участников.
- **Given** приглашённый, **When** он открывает приглашение, **Then** перед вступлением ему показывается согласие на обработку персональных данных (NFR-2).

### US-3. Заказ подростком в пределах лимита
> Как подросток-участник, я хочу оформить заказ сам, чтобы не ждать родителей, оставаясь в разрешённой сумме.

**Критерии приёмки:**
- **Given** подростку задан лимит 1500 ₽/неделя и потрачено 0 ₽, **When** он оформляет заказ на 900 ₽, **Then** заказ оформляется сразу, остаток лимита становится 600 ₽.
- **Given** остаток лимита 600 ₽, **When** подросток оформляет заказ на 800 ₽, **Then** заказ уходит на подтверждение владельцу, а подросток видит статус «Ожидает подтверждения».
- **Given** заказ ждёт подтверждения, **When** владелец отклоняет его, **Then** заказ отменяется, деньги с общего кошелька не списываются, подросток получает уведомление.

### US-4. Контроль трат владельцем
> Как владелец, я хочу видеть, кто и на сколько заказал, чтобы контролировать семейный бюджет.

**Критерии приёмки:**
- **Given** в аккаунте несколько участников, **When** владелец открывает историю заказов, **Then** по каждому заказу видно, какой участник его оформил и на какую сумму.

> Все истории соответствуют INVEST: независимы, обсуждаемы, ценны, оцениваемы, малы, тестируемы (критерии приёмки проверяемы).

## 5. Приоритизация MoSCoW

| Фича | Приоритет | Обоснование |
|---|---|---|
| Создание аккаунта, приглашение/удаление участников (FR-1…FR-3) | **Must** | Без этого фичи нет |
| Общие адреса и оплата (FR-4, FR-5) | **Must** | Главная ценность — заказывать на общее |
| Хранение автора заказа (FR-6) | **Must** | Нужно для контроля и поддержки |
| Лимиты и подтверждение (FR-7, FR-8) | **Should** | Сильно усиливает ценность для родителей, но v1 может выйти и без них на взрослых ролях |
| Общий список покупок (FR-9) | **Could** | Приятно, но не критично |
| Уведомления о заказах (FR-10) | **Could** | Улучшает прозрачность, можно позже |
| Раздельные выписки, банковские семейные карты | **Won't (v1)** | Высокая сложность, отдельная инициатива |

**Решение по v1:** Must + выборочно Should (лимиты для подростков), так как контроль трат — ключевой мотив родителей и прямой драйвер метрики retention.

## 6. Метрики успеха

| Метрика | Гипотеза | Как измерим | Срок проверки |
|---|---|---|---|
| Подключение семьи | ≥ 20% активных аккаунтов добавят участника | % аккаунтов с ≥2 участниками | 3 мес |
| Частота заказов | +15% у семейных vs контроль | A/B или сравнение когорт | 3 мес |
| Retention | +10 п.п. у семейных аккаунтов | когортный анализ | 6 мес |
| Обращения «чужой заказ/оплата» | −30% | теги обращений поддержки | 3 мес |
| Доля заказов подростков с подтверждением | мониторинг | доля заказов, ушедших на подтверждение | текущая |
