# Сценарии использования: CRM для сети фитнес-клубов

## UC-1. Онлайн-запись на групповое занятие

| Поле | Значение |
|---|---|
| Актор | Клиент (основной), система абонементов (вторичный) |
| Предусловие | Клиент авторизован, абонемент активен |
| Триггер | Клиент выбирает занятие в расписании |
| Результат | Создана бронь и зарезервировано место, либо предложена альтернатива |

Основной сценарий:
1. Клиент открывает расписание и выбирает занятие.
2. Система проверяет активный абонемент и остаток посещений.
3. Система проверяет свободное место.
4. Всё сходится — система создаёт бронь, уменьшает число свободных мест, отправляет подтверждение.

Альтернативы:
- 2a. Абонемента нет — система предлагает купить/продлить, бронь не создаётся.
- 3a. Мест нет — система предлагает лист ожидания (если включён) или другое занятие.
- 4a. Клиент уже записан на это занятие — повторная бронь не создаётся.

## UC-2. Продажа и продление абонемента

| Поле | Значение |
|---|---|
| Актор | Администратор |
| Предусловие | Клиент найден (или создаётся) |
| Триггер | Клиент хочет купить или продлить абонемент |
| Результат | Абонемент создан/продлён, оплата зафиксирована |

Основной сценарий:
1. Админ находит клиента по телефону.
2. Админ выбирает тариф (срок, лимит, цена).
3. Админ подтверждает оплату.
4. Система создаёт абонемент (статус «активен», даты, остаток посещений) и запись об оплате.

Альтернативы:
- 1a. Клиента нет в базе — админ заводит карточку (FR-1).
- 2a. У клиента есть активный абонемент — система предлагает продление, дата окончания увеличивается на срок тарифа.

## UC-3. Check-in и списание посещения

| Поле | Значение |
|---|---|
| Актор | Администратор |
| Предусловие | У клиента есть бронь/активный абонемент на сегодня |
| Триггер | Клиент пришёл в клуб |
| Результат | Посещение зафиксировано, остаток абонемента уменьшен |

Основной сценарий:
1. Клиент показывает QR или называет телефон.
2. Админ делает check-in.
3. Система фиксирует посещение, уменьшает остаток, помечает бронь «посещено».

Альтернативы:
- 3a. Клиент уже отмечен на это занятие — повторного списания нет (NFR-6).
- 3b. Абонемент истёк или заморожен — система блокирует check-in и показывает причину.

---

## UC-4. Заморозка абонемента

| Поле | Значение |
|---|---|
| Актор | Администратор / клиент |
| Предусловие | Активный абонемент, по тарифу заморозка разрешена |
| Триггер | Запрос на заморозку на период |
| Результат | Абонемент заморожен, дата окончания сдвинута |

Основной сценарий:
1. Указывается период заморозки.
2. Система ставит статус «заморожен» и сдвигает дату окончания на длину периода.
3. Пока абонемент заморожен, запись и check-in недоступны.
4. Период кончился — статус возвращается в «активен».
