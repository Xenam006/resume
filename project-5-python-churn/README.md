# Кейс 5. Исследование оттока клиентов на Python

Домен: телеком. Здесь я показываю полный цикл исследования в Jupyter: от сырых данных до рекомендаций, которые можно отдать в работу.

---

## Задача

Телеком-оператор теряет клиентов каждый месяц. Вопрос не в том, что отток есть, а в том, **кто уходит и почему** — чтобы удерживать не всех подряд, а тех, кого стоит, и правильным предложением.

---

## Что в ноутбуке

[`notebooks/churn_analysis.ipynb`](notebooks/churn_analysis.ipynb) идёт по шагам реального исследования:

1. **Данные.** Генерирую синтетический датасет по структуре *Telco Customer Churn* (Kaggle): контракт, срок жизни, счёт, способ оплаты, факт оттока.
2. **Очистка.** Проверяю типы, пропуски и аномалии.
3. **Разведочный анализ.** Смотрю, как отток зависит от типа контракта и срока жизни клиента.
4. **Проверка гипотез.** Хи-квадрат для связи «контракт — отток» и t-тест для разницы в счёте у ушедших и оставшихся.
5. **Модель.** Логистическая регрессия: предсказывает отток и показывает, какие признаки на него влияют.
6. **Выводы.** Что показывают данные и что с этим делать.

Данные синтетические и создаются в самом ноутбуке с фиксированным сидом, поэтому он запускается без внешних файлов и даёт воспроизводимый результат.

---

## Как запустить

```bash
pip install -r requirements.txt

```

Дальше «Run All» — ноутбук сам сгенерирует данные и посчитает всё до конца.

---

## К каким выводам приходит исследование

- **Помесячный контракт — главный фактор риска.** Перевод таких клиентов на годовой контракт (скидкой за переход) напрямую снижает отток.
- **Первый год — зона риска.** Новичкам нужен отдельный онбординг и внимание в первые месяцы.
- **Высокий месячный счёт повышает отток.** Таким клиентам стоит показать ценность тарифа или предложить более подходящий пакет, пока они не ушли.

Модель даёт вероятность оттока по каждому клиенту — её можно выгружать в CRM и запускать удержание по списку с самым высоким риском, а не по всей базе.
